## 标题、提示与内容核对

已修正四处事实性描述：

1. 记忆库顶栏/空态原先泛称“翻译过的内容自动入库”，现在明确 Excel、Word 和符合入库条件的内容。PDF 不按普通文本记忆库流程入库，混合或不确定源语言也不能泛称会自动入库。
2. README 原先声称首次启动不会读取、迁移或修复旧数据，与当前目录的兼容读取和损坏恢复机制冲突。现在区分其他目录导入与当前目录兼容处理，并说明失败时保留原件。
3. KNOWN_ISSUES 原先称图片相关扫描字段已移除。实际 `.xlsx` 独立扫描仍统计图片、含文字形状和批注；`.xls` 为未知值，不是零。现已按实现更正。
4. Excel“仅显示译文”原先称整个输出文件只保留译文，与独立「_原文」副本选项冲突。现在明确仅作用于翻译后的工作表，原文副本单独控制。Word 的说明不作同样改动。

帮助页“最多两种实际源语言”有预检提示及响应裁剪逻辑支持；Office 说明与旧格式转换需确认回退、标准格式可使用 Python 路径的实现一致。诊断包的匿名归档入口与现有隐私动态测试相符。未发现这些说明存在已证实的事实冲突；跨平台原生转换仍需要设备验收。

## 后续优化建议

**优先推荐把真实前端状态回归接入日常检查。** 本轮冷启动问题说明，仅检查界面文案或单个渲染函数无法证明连接顺序正确。已提供可复用测试，接入质量门/CI 属于检查配置变更，待确认后另派子任务执行。建议先做这一项，避免再次出现“静态检查通过、实际页面不显示”的问题。

其后建议集中核对前后端重复定义的选项默认值，并测试升级后默认值的一致性。现阶段未确认具体默认值已漂移，不将其列为已发现 bug。

跨目录多选文件、维护检查与新任务恰好同时发生的极窄并发窗口，以及重启后继续查看 PDF 单页版本记录，作为下一轮定向验证/产品讨论项。本轮未取得充分复现证据，未据此修改行为；重启后单页记录能力扩展需要先明确保存内容和保留期限。
