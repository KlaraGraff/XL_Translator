# 发布说明

每个版本一份 `v{版本号}.md`，内容就是 GitHub Release 的正文，原样替换上去。
和代码一样走 PR 合进 main，`release.yml` 的 publish 步骤只读 main 上的这份文件。

写法见 `AGENTS.md` 第 9 条，简单说：

- 读者是普通用户。每条一个粗体小标题，跟一两句「原来什么样、现在什么样」，不写术语。
- 先 `## 中文`，后 `## English`，两边逐条对应。
- 结尾列下载：每个平台一行文件名，加一句安装提示。
- 签名、公证状态以当次构建的实际渠道为准（草稿 Release 里那一行 `Channel:`）。
- 正文第一条 `---` 以上的内容会显示在应用内「更新与关于」页，安装包清单、
  校验和签名提示放在 `---` 以下（没有 `---` 时整篇都会显示在应用内）。

publish 前 `scripts/check_release_notes.py` 会机械核对：不能是占位句、中文在前、
下载文件名与 Release 上实际的安装包一致、正式渠道不许写「未公证」、临时渠道必须写「未公证」。
发布后要改正文，改这里的文件合进 main，再运行 `step=notes`。
