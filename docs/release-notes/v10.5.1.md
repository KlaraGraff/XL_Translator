## 中文

### 新功能

**窗口顶部更简洁**
去掉了窗口最上面单独的系统标题栏。Mac 上红绿灯按钮放进左侧栏的左上角；Windows 上右上角换成软件自己的最小化、最大化、关闭按钮。拖动侧栏顶部或页面空白处可以移动窗口，双击可以放大或还原。

**扫描列表可以再次拖入文件**
页面上已经有一份还没开始翻译的文件清单时，再拖文件进来会提示「松手添加到当前列表」，松手后新文件加进清单，不再把原来的清单换掉；已经在清单里的文件不会重复加入。刚翻译完、正在看结果时拖入，则算新的一批。

### 改进与修复

**PDF 转 Word：WPS 里表格不再挤成竖排**
转出的 Word 用 Microsoft Word 打开正常，但用 WPS 或网盘预览打开时，表格正文列会被挤得很窄。现在表格列宽写对了，各软件打开都一样。

**PDF 转 Word：一页原文仍排成一页译文**
译文比原文长时，以前一页排不下就挤到下一页，例如 3 页的表格变成 5 页，页码也跟着错位。现在放不下的那一页会自动缩小字号（最多缩到七成），放得下的页不动。

**PDF 转 Word：页眉左右两块不再上下叠起来**
页面顶部左右并排的两块内容（例如姓名框和编号框），在 WPS 里以前会上下叠起来，多占好几行。现在用无边框表格排列，Word 和 WPS 里都左右并排。

**模型回答太长被截断时，拆小重发**
一批译文太长、模型回答写到长度上限被截断时，以前会把同一批原样重发几次，每次都被截断、每次都计费，最后整批保留原文。现在改为拆成小批再发，日志里也会写明是「被截断」。

**Word 续译：表格里有修订时不再整份重翻**
选「修订一起翻译」翻过的文件，表格里有修订时，点续译会放弃上次结果、整份从头翻。现在只补没翻完的部分。

**Word 双语输出的修订编号不再重复**
带「新插入的段落」这类修订标记的段落，双语输出时译文段和原文段的修订编号相同，在 Word 里接受或拒绝修订可能作用到另一段。现在译文段换用新编号。

**记忆库整库导入出错时不留半截**
恢复记忆库备份时如果中途出错，以前已经写进去的一部分会留下，再导一次数字就对不上。现在出错时整体撤回，库和自定义语言都回到导入之前。

**多个任务同时翻译时更快**
几个任务共用同一个模型连接时，排在最前面的大请求暂时放不下，后面放得下的小请求可以先发，空出来的并发不再闲着。

**从两个文件夹拖进同名文件**
以前会拒收并提示改名。现在照常翻译，名字撞了的译文分别放进以来源文件夹命名的子文件夹，例如「二期/清单_英文.xlsx」，不会互相覆盖。

**稳定性**
整理了程序内部结构，删掉不再使用的旧代码，出错时多记一条日志，方便以后排查问题。软件的使用方式没有变化。

## English

### New features

**A cleaner window top**
The separate system title bar at the top of the window is gone. On Mac, the window buttons now sit in the top-left corner of the sidebar; on Windows, the minimize, maximize and close buttons are drawn by the app in the top-right corner. Drag the top of the sidebar or an empty area of the page to move the window, and double-click to maximize or restore it.

**Drop more files onto the scan list**
When a file list that has not been translated yet is already on the page, dragging more files over it shows "Drop to add to the current list", and dropping adds the new files instead of replacing the list; files already in the list are not added twice. Dropping while the results of a finished translation are shown starts a new batch.

### Improvements and fixes

**PDF to Word: tables no longer squeezed in WPS**
Converted Word files looked right in Microsoft Word, but in WPS or online previews the main table column was squeezed very narrow. Table column widths are now written correctly, so every app shows the same layout.

**PDF to Word: one original page stays one translated page**
When the translation was longer than the original, a page that did not fit used to spill onto the next one, for example a 3-page form becoming 5 pages with shifted page numbers. A page that does not fit now gets a smaller font size automatically (down to 70% at most), and pages that fit are left unchanged.

**PDF to Word: side-by-side header blocks no longer stack**
Two blocks placed side by side at the top of a page (such as a name box and a number box) used to stack on top of each other in WPS, taking several extra lines. They are now laid out in a borderless table and stay side by side in both Word and WPS.

**Answers cut off at the length limit are resent in smaller batches**
When a batch's translation was too long and the model's answer was cut off at its output limit, the same batch used to be resent several times, cut off and billed each time, and finally left untranslated. It is now split into smaller batches and resent, and the log says the answer was cut off.

**Word resume no longer retranslates the whole file when tables contain tracked changes**
For a file translated with "Translate the changes too", tracked changes inside a table made Resume discard the previous result and translate the whole file again. Resume now fills in only what is missing.

**No more duplicate revision IDs in Word bilingual output**
For paragraphs carrying a tracked change such as "inserted paragraph", the translation paragraph got the same revision ID as the original, so accepting or rejecting a change in Word could affect the other paragraph. The translation paragraph now gets new IDs.

**A failed full translation memory import leaves nothing half done**
If restoring a translation memory backup failed partway, the part already written used to stay, and importing again gave mismatched counts. A failure now rolls everything back, so the memory and custom languages are as they were before the import.

**Faster when several tasks run at once**
When several tasks share one model connection and the request at the front of the queue does not fit yet, smaller requests behind it that do fit can go first, so free capacity is no longer left idle.

**Same-named files dropped from two folders**
These used to be refused with a request to rename one. They are now translated, and translations whose names would clash go into subfolders named after the folder each file came from (for example "Phase 2/List_English.xlsx"), so neither overwrites the other.

**Stability**
The app's internal structure was tidied up, unused old code was removed, and more errors are now logged to make problems easier to track down. Nothing changes in how the app is used.
