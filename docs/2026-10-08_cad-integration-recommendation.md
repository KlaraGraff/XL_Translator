# CAD/DWG 接入 Translator：插件化推荐方案

## 推荐结论

建议把 CAD 做成一个**可选的 CAD 支持插件**，而不是把 ODA 转换器直接塞进 Translator 主安装包：

- Translator 主程序保留现有 Excel、Word、PDF 能力，默认不增加 CAD 依赖。
- 用户在“插件与能力”里点击“安装 CAD 支持”，明确确认平台和许可后，下载安装 CAD 适配器。
- CAD 适配器负责 DWG/DXF 解析、实体文字筛选、翻译编排、ODA 调用和 DWG 写回；任务中心、断点、事件流、历史记录继续复用主程序。
- ODA 不作为我们捆绑的隐藏组件。插件先检查本机是否已有 ODA；没有时提供“从官方来源获取”或“选择已安装目录”两个动作。

这样既能让用户点击启用 CAD，也能避免把有独立许可的转换器伪装成 Translator 的内置组件。用户卸载 CAD 插件时，Excel/Word/PDF 不受影响。

## 插件安装和启用

插件页面建议只显示用户真正需要的状态：

| 状态 | 用户动作 | 结果 |
| --- | --- | --- |
| 未安装 | 安装 CAD 支持 | 下载并校验当前平台的插件包，安装到应用数据目录 |
| 安装中 | 查看进度 / 取消 | 保留临时包；取消后不改变现有能力 |
| 已安装但 ODA 缺失 | 获取 ODA / 选择目录 | 只在用户点击后打开官方获取流程或本机目录选择 |
| 已启用 | 打开 CAD 图纸 | 进入 CAD 工作区并复用任务中心 |
| 不兼容 | 查看原因 | 显示 macOS 版本、CPU 架构或 Windows 版本要求 |
| 损坏或版本过旧 | 修复 / 更新 | 下载新插件，旧版本仍保留到校验成功后再替换 |

插件包应有版本、目标平台、最低应用版本、SHA-256、下载地址和签名信息。安装过程先下载到临时目录，校验通过后原子替换；不能把半个插件目录当成“已安装”。更新失败时继续使用上一个完整版本。

ODA 的自动获取要单独展示许可说明。用户点击后可以打开官方下载页或执行经过确认的官方下载流程；如果当前许可不允许产品代为分发，就只提供“选择本机已安装 ODA”路径。官方资料列出的访客转换器支持 macOS 13+（Apple Silicon/Intel）和 Windows 10+ x64，但 ODA FAQ 对非会员使用范围有额外限制。因此，“点击安装插件”不等于我们可以自由打包或转发 ODA。

## CAD 工作区和运行过程

CAD 插件启用后，在侧栏出现“CAD 图纸”。这个页面只负责 CAD 任务的输入和预检；任务运行状态进入统一任务中心，不能再做一套独立的进度系统。

用户流程为：

1. 选择 DWG、DXF 或文件夹。原件只读，输出写入独立结果目录。
2. 预检显示插件版本、ODA 状态、平台、可见文字数量、字体风险、不可处理对象和预计 AI 请求量。
3. 任务中心显示五个阶段：读取图纸 → 匹配记忆/术语 → AI 翻译 → 写回 DWG → 打开校验。
4. 运行中按文件显示进度，可暂停、继续或停止并保存断点；单文件失败不拖垮批次。
5. 完成后给出 DWG、manifest、校验报告和待审阅文字；用户修改后可选择“仅保存本次修改”或“加入记忆库”。

## 页面与右侧设置设计

CAD 页面沿用 Translator 现有的左侧导航、顶栏和两栏工作区。左栏负责文件与任务，右栏只放本次任务的设置，不把平台安装、长期术语库和临时参数混在一起。

左栏从上到下建议是：

1. 文件选择条：添加文件、添加文件夹、移除、清空；显示原件只读提示。
2. 文件表：文件名、格式、图纸空间/布局数量、可见文字数、预检状态、当前进度。
3. 运行面板：当前阶段、当前文件、阶段进度、最近日志和暂停/停止按钮。
4. 结果面板：输出 DWG、校验报告、manifest、待审阅条目和打开目录按钮。

右栏设置分成四组：

| 分组 | 设置 | 默认建议 |
| --- | --- | --- |
| 翻译 | 源语言、目标语言、只翻译指定语言、跳过已是目标语言 | 源语言自动识别；跳过目标语言开启 |
| 记忆与术语 | 用户记忆库、项目术语库、术语强制匹配、未命中时是否请求 AI | 用户记忆库开启；术语库可选；未命中请求 AI |
| 输出 | 输出目录、保留工作 DXF、是否复制关联文件 | 独立结果目录；工作 DXF 默认保留到任务目录 |
| 检查 | 写回后重新读取、实体/文字数量检查、检查文字乱码、残余外文扫描 | 四项全部开启 |

插件和 ODA 状态放在“设置 → 更新与关于 → 插件与能力”，不放在每次任务的右栏。右栏只显示一行状态，例如“CAD Support 1.0.0 · ODA 已连接”。

## 进度计算建议

任务总进度按可验证工作量分配，不按等待时间分配：

| 阶段 | 权重 | 阶段内部的细分 | 进度含义 |
| --- | ---: | --- | --- |
| 读取与扫描 | 15% | 文件发现 3%、转换/读取 7%、可见文字扫描 5% | 已经完成扫描的文件占比 |
| 记忆与术语匹配 | 10% | 规范化去重 4%、记忆库 3%、可选术语库 3% | 已完成匹配的文本条目占比 |
| AI 翻译 | 45% | 已发送批次占 35%、返回并通过基础校验占 10% | 已完成批次/总批次，并显示重试 |
| 写回 DWG | 20% | 文本定点写回 10%、DXF→DWG 6%、输出文件落盘 4% | 已完成写回的文件占比 |
| 打开与校验 | 10% | 重新读取 3%、结构/文字计数 3%、乱码 2%、残余外文/报告 2% | 已完成校验的文件占比 |

界面同时显示两种数值：**总进度**和**当前阶段进度**。例如“总进度 64%，AI 翻译 73%（1,806/2,825 条）”。这样用户不会把“AI 批次完成”误认为“DWG 已经写回”。

“写回后重新读取”是把生成的 DWG 再读一遍，确认文件能正常解析、实体数量和文字数量没有异常；“检查文字乱码”是检查输出文字中是否出现 `�`、问号或其他乱码替代字符。前者验证文件结构，后者验证文字内容。

不可预测的插件下载、ODA 探测和模型等待不伪造百分比：安装阶段使用不定进度条并显示已下载大小；模型请求等待时保留当前阶段百分比，旁边显示“等待接口返回”，失败重试不重复增加进度。

文件级进度采用同一套阶段权重，但以该文件的可处理条目和批次数计算。批量总进度按文件的工作量加权，不能简单按文件数量平均，否则一个大型图纸会在视觉上被低估。

## 运行状态和阻塞反馈

运行区固定显示：阶段名称、阶段百分比、当前文件、总体百分比、已完成/总条目、预计剩余批次和最近三条日志。状态颜色只使用现有 Translator 的运行、成功、警告、暂停和危险色。

- **扫描中**：显示“发现文件、读取布局、扫描可见文字”；ODA 未连接时在这里阻塞并给出“去安装/选择目录”。
- **翻译中**：显示批次进度、记忆/术语命中数、AI 请求重试数；不显示不可靠的剩余时间。
- **写回中**：显示当前实体类型、DXF→DWG 是否成功和输出路径是否已落盘。
- **校验中**：显示文字实体数、乱码数、残余外文数和未支持对象数。
- **暂停**：说明“当前文件完成后暂停”，已完成输出保留；停止确认使用危险模态，强调可从断点继续。
- **部分完成**：任务显示“已生成但需复核”，不能把有遗漏的结果显示为全绿成功。
- **失败**：明确失败阶段和下一步动作；保留中间 DXF、日志和诊断报告，允许从失败阶段重试。

## 插件安装状态机

插件安装独立于 CAD 翻译任务，状态为：未安装 → 检查平台 → 下载 → 校验 → 安装 → 需要重启 → 已启用；任一步失败进入“安装失败”，保留旧版本并提供“重试”或“改为下载安装包”。

ODA 同样独立探测：未找到 → 选择本机目录/打开官方下载页 → 验证版本和架构 → 已连接。官方获取动作完成后不能直接显示“已安装”，必须由本机探测确认可执行文件、版本和架构。

## 翻译解析链

CAD 不应继续使用“TM 命中，否则直接问模型”的简化路径。插件内应使用明确的 resolver：

1. **用户记忆库**：沿用现有 TM 的人工/置顶优先级。用户编辑过的译法覆盖自动结果。
2. **可选项目术语库**：独立、可导入导出；包含原文、译文、语言对、领域、强制标记、版本和来源。未安装或未启用术语库时，流程仍可运行。
3. **AI 翻译**：只发送前两层没有解决的可见文本，并把命中的术语作为固定译法传入请求。模型输出经过术语一致性、数字和格式占位符检查后才写回。

MTEXT、MULTILEADER、ATTRIB/ATTDEF 按实体类型处理：保护格式码和结构标记，按去格式的规范文本去重，写回时恢复原有分片顺序；属性标签、提示、块名、图层名、字体名和隐藏脚本不按普通文字翻译。残余外文扫描只报告可见文字，结构信息单独列出。

## 转换后端和跨平台边界

ODA File Converter 继续作为默认 DWG 写回后端，但由插件 runner 调用，而不是由主程序直接依赖。runner 负责：

- DWG → 工作 DXF；
- 原始实体文本的定点修改；
- DXF → 新 DWG；
- 重新读取、实体计数、文字计数、乱码和残余可见外文检查。

原始 DWG、工作 DXF 和最终 DWG 分目录保存；失败时保留中间文件和报告。ezdxf（MIT）可复用作 DXF 解析、实体检查和测试辅助，但在没有保真度证明前，不让它重写整张复杂图纸。

Translator 当前最低 macOS 是 12.0，而 ODA 转换器要求 macOS 13+，所以插件在 macOS 12 上显示不兼容，其他翻译能力继续可用。Windows 10 x64 与 macOS 13+ 必须使用同一组夹具做真实转换、打开和文字计数回归后，才宣称双平台支持。

## 分阶段落地

### 第一阶段：插件骨架和可控试用

实现插件清单、安装/校验/卸载、平台检查、ODA 探测和 CAD runner；接入任务中心，支持普通 DWG/DXF、T3、可见文字翻译、输出新 DWG、报告和断点。术语库保持可选。

### 第二阶段：质量闭环

加入独立术语库、格式占位符保护、实体类型专用写回、逐条审阅和人工修改回写记忆。每个输出生成 manifest，记录源文件哈希、插件/转换器版本、记忆命中、术语命中、AI 调用、写回变化、跳过项和校验结果。

### 第三阶段：双平台和关联打包

在 Windows 10 x64 和 macOS 13+ 上跑完整回归，增加文件夹级批量，并把 DWG 与同目录 PDF 的原件/译件关联打包。只有同名、路径和哈希都能确认时才自动配对，避免把旧 PDF 错装进新任务。

## 验收门槛

- 插件安装可取消、可恢复；校验失败不替换旧版本。
- 原件哈希不变，输出与原件一一对应；不覆盖源文件。
- 任务可暂停、恢复、重试；单文件错误可定位到读取、翻译、写回或校验阶段。
- 至少覆盖 MTEXT、TEXT、ATTRIB、ATTDEF、MULTILEADER，并证明结构控制码未被翻译。
- AI 请求只包含可见、可翻译文本，能追溯记忆、术语和 AI 的来源。
- 输出 DWG 在 Windows 和 macOS 目标 CAD 中打开；文字实体数、关键结构和乱码检查通过。
- 字体、代理对象、未支持对象和残余外文分别报告，不把“文件能打开”当成“排版完全正确”。
