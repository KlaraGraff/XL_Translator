这份样张里已经替你定了的几件事

  1. 「导出（不含 Key）」按钮保留。 有时候就是不想给密钥，只想给对方一套连接和参数，这个需求没消失。
  2. 有效期只锁密钥，不锁配置。 配置部分本来就是明文，过期拦下来没有任何收益（界面 5）。
  3. 只有「导出（含 Key）」换成 .xltcfg。 加密之后打开只有乱码，换个扩展名断掉用记事本打开的念头。「导出（不含 Key）」仍是 .json——那份文件本来就是纯 JSON，而 9.2.4 及更早版本的导入选择器只接受 .json，换掉会让还没升级的收件人在文件框里根本选不中它。导入两种都收。
  4. 文件里带密钥编号。 将来内置密钥万一外泄，下个版本换一把就能补救，旧文件也还读得开（界面 6）。不现在留这个口子，以后就补不上了。
  5. 内置密钥不写进源码，发版时从 GitHub Actions 的加密变量注入。否则密钥就直接躺在你的公开仓库里，连下载安装包这一步都省了。
